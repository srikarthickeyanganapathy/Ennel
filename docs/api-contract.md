# ENNEL API Contract (draft)

Status: **Phase 1–4 endpoints implemented** (marked ✅, detailed in §2.1–2.3, §3.1 and §3.2). Conventions are fixed. The rest of the inventory is a plan, and each phase finalizes its endpoints here and in Swagger (`/api/docs`). Request/response schemas are the Zod schemas in `@ennel/shared/schemas`.

## 1. Conventions

| Topic       | Rule                                                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Base paths  | Student `/api/v1`, staff `/api/v1/admin`                                                                                                       |
| Resources   | Plural kebab-case nouns (`/bookings`, `/no-show-appeals`); actions as sub-resources (`POST /bookings/{id}/cancel`)                             |
| JSON        | `camelCase`; dates `YYYY-MM-DD` (IST business date); instants ISO-8601 UTC (`2026-10-19T04:30:00.000Z`); clients format them in IST with AM/PM |
| Auth        | `Authorization: Bearer <access>`; refresh via `POST …/auth/refresh` with the refresh token in the body (mobile) or an httpOnly cookie (admin)  |
| Idempotency | `Idempotency-Key: <uuid>` **required** on booking create/change/cancel, leave create/extend/end, complaint create                              |
| Concurrency | Edited records carry `version`; send it back on PATCH; a stale version returns `409 VERSION_CONFLICT`                                          |
| Overrides   | Admin overrides require `reason` (non-empty, ≤500 chars), else `422 OVERRIDE_REASON_REQUIRED`                                                  |
| Request ID  | Responses carry `X-Request-Id`; also echoed in error bodies                                                                                    |

### 1.1 Lists

Query: `page` (≥1, default 1), `pageSize` (1–100, default 20), `sortBy`, `sortOrder` (`asc`|`desc`), `q`, plus resource filters.
Response: `{ "items": [...], "total": 123, "page": 1, "pageSize": 20 }`.

### 1.2 Errors

```json
{
  "code": "BOOKING_DEADLINE_PASSED",
  "message": "Cancellation closed at 10:00 AM.",
  "details": { "deadlineAt": "2026-10-19T04:30:00.000Z" },
  "requestId": "…"
}
```

| Code                       | HTTP | Meaning                                            |
| -------------------------- | ---- | -------------------------------------------------- |
| `VALIDATION_FAILED`        | 400  | Input failed schema validation (`details.issues`)  |
| `UNAUTHENTICATED`          | 401  | Missing/invalid/expired token or wrong audience    |
| `INVALID_CREDENTIALS`      | 401  | Login failed (no hint whether the account exists)  |
| `ACCOUNT_LOCKED`           | 423  | Lockout or staff-locked account                    |
| `PASSWORD_CHANGE_REQUIRED` | 403  | Staff must change password before other calls      |
| `PERMISSION_DENIED`        | 403  | Missing permission                                 |
| `NOT_FOUND`                | 404  | Resource missing or not visible to caller          |
| `VERSION_CONFLICT`         | 409  | Optimistic-lock mismatch                           |
| `IDEMPOTENCY_KEY_REUSED`   | 409  | Same key, different payload                        |
| `ROSTER_NOT_FOUND`         | 404  | Reference number not in the active roster          |
| `ALREADY_REGISTERED`       | 409  | Reference number already has an account            |
| `BOOKING_DEADLINE_PASSED`  | 422  | Cancel/change/diet deadline passed                 |
| `SLOT_UNAVAILABLE`         | 422  | Slot full (no over-capacity), disabled, or closed  |
| `BOOKING_NOT_ALLOWED`      | 422  | Date outside horizon, on leave, or mess closed     |
| `LEAVE_RANGE_INVALID`      | 422  | End before start, overlap, or invalid resume point |
| `OVERRIDE_REASON_REQUIRED` | 422  | Missing reason on an override                      |
| `ROSTER_IMPORT_INVALID`    | 422  | Import confirm attempted with blocking errors      |
| `FILE_INVALID`             | 422  | Upload type/size invalid                           |
| `RATE_LIMITED`             | 429  | Too many requests                                  |
| `INTERNAL_ERROR`           | 500  | Unexpected failure (no internals leaked)           |

| ------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

### 2.3 Phase 4 endpoints (booking engine)

Writes need an `Idempotency-Key` header (a UUID, ADR-0016): a retry with the same key and request replays the first response; the same key with a different request returns `409 IDEMPOTENCY_KEY_REUSED`; a missing key returns `400 VALIDATION_FAILED`. Each write returns the updated meal card (`mealCardSchema`), so the app can redraw that one card.

| Endpoint                            | Body → response                                                             | Errors                                                                                                                                                                                | Notes                                                                                                                                                                                                                                                          |
| ----------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /days/{date}`                  | → `DayResponse` (3 meal cards)                                              | `BOOKING_NOT_ALLOWED` outside today … today + horizon                                                                                                                                 | Each card has `label` (BR-BOOK-3), `appliedRule` (ADR-0014), the booking (slot, meal type, status, source, `isUpdatedByStaff`, `version`) and `actions.book / changeSlot / changeDiet / cancel`, each with `allowed`, `reason` and `deadlineAt` for countdowns |
| `POST /bookings`                    | `bookMealRequestSchema` → card (201)                                        | `SLOT_UNAVAILABLE` (full, disabled, started, wrong meal), `BOOKING_NOT_ALLOWED` (closed, on leave, already booked, outside the period)                                                | Writes a one-day BOOK date exception and the booking (source `MANUAL`) in one transaction; the seat is checked under the slot/date lock (ADR-0004). A cancelled meal can be booked again                                                                       |
| `PATCH /bookings/{id}`              | `changeBookingRequestSchema` (`slotId` and/or `dietType`, `version`) → card | `BOOKING_DEADLINE_PASSED` (slot change closes at slot start, meal type `dietTypeChangeCutoffMinutes` before), `SLOT_UNAVAILABLE`, `VERSION_CONFLICT`, `NOT_FOUND` (not the student's) | This date only; recurring preferences are untouched (Rule 5)                                                                                                                                                                                                   |
| `POST /bookings/{id}/cancel`        | → card                                                                      | `BOOKING_DEADLINE_PASSED` (`cancellationCutoffMinutes` before slot start), `NOT_FOUND`                                                                                                | Writes a SKIP date exception, so the nightly job never re-creates it                                                                                                                                                                                           |
| `POST /days/{date}/cancel-eligible` | → `{ cancelled, notEligible[{ mealType, reason }], day }`                   | `BOOKING_NOT_ALLOWED`                                                                                                                                                                 | Spec §4.4, BR-DEAD-6                                                                                                                                                                                                                                           |

| ----------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

### 3.1 Phase 2 notes

Schemas live in `@ennel/shared/schemas/admin`. Every admin mutation writes one audit entry in its transaction (BR-ADM-1). Routes that change student-facing rules or accounts take a `reason`; edits of versioned records take `version` and may return `VERSION_CONFLICT`.

| Endpoint                                            | Body → response                                                                                                                          | Errors / notes                                                                                                                                                                                                       |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /admin/auth/login`                            | `staffLoginRequestSchema` → `{ status: AUTHENTICATED, session }` or `{ status: TOTP_REQUIRED, challengeToken }`                          | `INVALID_CREDENTIALS`, `ACCOUNT_LOCKED`, `RATE_LIMITED`. Sets the `ennel_staff_refresh` cookie (httpOnly, SameSite=Strict, path `/api/v1/admin/auth`) only once fully authenticated                                  |
| `POST /admin/auth/totp/verify`                      | `totpLoginRequestSchema` → `StaffSession`                                                                                                | Challenge token valid 5 minutes. Wrong codes count towards lockout                                                                                                                                                   |
| `POST /admin/auth/refresh`                          | cookie → `StaffSession`                                                                                                                  | Rotates the cookie; reuse revokes the session family. `session.mustChangePassword` true → every other route returns `PASSWORD_CHANGE_REQUIRED` until `POST /admin/auth/change-password`                              |
| `POST /admin/auth/change-password`                  | `changePasswordRequestSchema` → `StaffSession`                                                                                           | Revokes the staff member's other sessions                                                                                                                                                                            |
